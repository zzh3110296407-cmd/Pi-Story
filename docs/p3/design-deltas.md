# P3 实现与设计差异

日期：2026-11-01。依据 27、29 与 13 的 P2 采纳附录。产品改变只在开发部分验证，冻结后不依据验收输出调规则。

## U7（方案已授权）

内部角色每个逻辑调用最多一次传输重试；每次独立预留、结算与记录。CallRecord 新增可选 `id`、`retryOf`、`failure`；ModelPort 返回结构新增可选 `failure={kind:transport|rejected|fatal|aborted,httpStatus?,retryAfterMs?}`。旧冻结调用记录可缺省这些字段，新调用总是带预留编号作为 id。JSON 修复调用不带 retryOf，传输重试引用被重试的预留编号。原标准流程 14 次逻辑调用，中断保守上限改为 28 次。领域校验与内部角色规则保持不变。

固定 Pi 的主笔重试：`packages/coding-agent/src/core/settings-defaults.ts` 默认启用 agent 层重试，最多3次、起始2秒退避；`agent-session.ts` 先排除上下文溢出，再按 `pi-ai/utils/retry.ts` 的暂时错误分类，取消和配额/账单限制不重试。DeepSeek 走 openai-completions API，SDK 自带重试关闭，provider-retry 的缺省次数为0，可由设置覆盖。扩展不再增加主笔重试。每次实际主笔请求仍须经 S6 的预算挂点。P3 测量驱动需显式记录所用 Pi retry 设置；P2 的历史设置与结果不改。

core 只改变调用会话、调用记录契约与中断费用上限；未改 foundation/plan/canon/production 的领域规则。全 P1 回归、针对性故障测试与项目检查见执行记录 S1。

## 作者命令编辑框（27 S2 的明确要求）

12 §4 对无参 goal/budget 写“显示”；27 S2 统一要求无参数打开预填编辑框，本实现按27为五个命令提供编辑框。无UI时要求显式参数，不猜测作者意图；取消不写入。ledger编辑框每行使用 add/set/remove 命令语法，整批由core校验后写入，空白行忽略。编辑框关闭后重读最新分支，避免覆盖期间发生的作者命令。通知只提醒，权威仍是 story.control/story.goal。

## 主笔规则（S3，开发初版）

保留开书规则与原话边界，增加连续写作、必要时问作者、未来修改与理由、插话和错误停止。系统提示由固定规则及三个动态段组成，进度取core投影。27的DS14要求600–900词短章，故主笔遵从作者明确的单章短目标；没有明确单章目标时仍沿用1200词及默认10章。内部角色规则、设置不改。主笔规则开发调优最多2轮；本次为实现初版，尚无真实模型调优或冻结。

## 预算完整快照（DD03/R2 的接线）

首次作者策略命令先取得全局默认预算，再交core保留另一项；已有story.goal后仅使用该完整策略，budget缺省表示off，不回退到默认。每次预留重新从当前分支取得有效预算。该接线修复在适配层。

作者已授权最小预算契约调整：具体BudgetGuard用BudgetCallRecord（role:string）结算原生主笔/压缩预算，内部角色CallRecord schema、领域端口与领域校验均未改变。check无副作用，summary把在途与待确认义务纳入，避免适配层另建金额状态。主笔已知用量仅在Pi原生条目保存后按对象身份确认，未知用量留作进程内预留；跨进程中断恢复仍属P4。

固定Pi的压缩摘要绕过主笔onPayload挂点，实际反例在两次摘要HTTP前均无在途预留。作者已接受[临时兼容处理](compaction-compatibility.md)：仅压缩期间通过公开provider接口逐次预留与结算，成功/失败均恢复原注册，Pi算法、认证与重试不改。成功压缩按原生聚合只计一次，失败或未知义务保留。上游修复或升级后重测再删除本兼容层。

## 测量协议的开发状态

S10开发发现update_bible的value以任意对象公开，而core人物卡片只接受identity/socialPosition/drive/psychology/abilities/limits/voice/embodiment/secrets/arc/invariants。模型提交skills时先通过工具参数再被core拒绝。适配层现按kind公开人物专用value，直接引用core既有卡片schema；其他种类保留原属性对象。未新增或放宽领域字段，原来成功的参数仍有效。回归先复现skills错误获准，再验证skills在工具边界被拒、abilities仍可提交及相邻工具流程通过；core不改。

Pi导出的RpcClient没有extension_ui_response发送接口，故P3测量层补齐JSONL传输及对话框转发，未修改上游。整书驱动在成功大纲回执时设min(大纲末章,10)，核对goal确实保存，之后不发送追加作者提示。

开发评分器按各章实际write_next_chapter工具结果计尝试；未能提交但已尝试的章保留，尚未尝试的目标章另报。S03只以已尝试章为n，仍须≥40；T08以完成提交的章为n、统计上次提交后至本次提交的主笔回复数，须≥20。S01核对实际正史、提问及goal后的作者操作，须5本；低样本量不得判通过。以上仅开发实现，完整测量协议仍须在S10之后、验收之前冻结。

S10后测量说明：T08改为实际HTTP派发数，包含主笔原生重试；T01依16的全部真实运行汇总、最少100次。P3-OPEN固定一次12条，T05使用16的10条最少样本及90%阈值，未沿用P2专用24条默认；旧评分行为不改。OPEN到成功大纲为止，后续由测量驱动取消的未执行工具结果单列，保留原始回执，不算模型参数错误。SDK会公开cwd，故评测工作目录必须使用摘要名；旧开发目录编号曝光已披露，未涉及验收内容或金标，正式运行在修复后执行。
