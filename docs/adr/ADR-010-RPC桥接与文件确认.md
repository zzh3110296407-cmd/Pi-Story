# ADR-010：RPC 桥接与文件确认

日期：2026-10-28。依据：V21–V24、V28，自动验证完成。

## 背景与选项

比较每故事独立 Pi RPC 进程与一个进程 switch_session。桥接仅监听 127.0.0.1，启动令牌一次性换取 HttpOnly、SameSite=Strict cookie，并校验 Host 与 Origin。RPC 按 LF 分帧。

## 决定与 V21 依据

优先每个活动故事独立进程，生命周期、插话和故障归属更直接。V21 两个进程启动约 809/712 ms，工作集约 126/126 MiB；另一个进程启动约 709 ms，切换两个已有会话约 25/20 ms，工作集约 135 MiB。样本仅两个故事、两次切换，不能据此推断容量或性能分布。实际产品需限制并发活动故事。

不存在的显式 session-id 能创建会话。HTTP 新建、列表、重开、消息、steer、clear_queue 加 abort、编辑框回答，WebSocket 事件与真实 Edge 网页往返均通过。截图视觉检查确认中文、按钮与输入区域可读；编辑框交互由 DOM 断言验证。证据：`D:\开源\test\pi-Story\p0\runs\V21\2026-10-28T10-39-37-219Z\result.json`。

HTTP 发消息立即返回 202，命令最终响应另经 WebSocket 发送。需要等待作者的命令不能让 HTTP 响应悬挂十分钟。V23 实测 setStatus 的 statusKey=story、statusText=working 原样到达 WebSocket，无需从其他事件猜测状态。证据：`D:\开源\test\pi-Story\p0\runs\V23\2026-10-28T10-40-59-187Z\result.json`。V22、V28结果如下。

## V22 长等待与首次写盘

已有普通对话的会话中，编辑框实际等待600005.8641ms，没有提前完成或取消；回答后控制条目与会话文件内容一致。HTTP接受约1.6ms，未悬挂等待作者；该命令RPC上限显式为十五分钟，客户端普通请求默认上限仍是三十秒。证据：`D:\开源\test\pi-Story\p0\runs\V22\2026-10-28T11-26-07-121Z\result.json`，成功样本一次。

前一个未初始化夹具虽完成十分钟等待和回答，但文件核对ENOENT：Pi要求出现普通user或assistant消息才创建新文件，只有handled扩展命令不够。修正后先完成一轮替身对话，文件存在断言通过才开始计时；没有修改Pi。失败证据保留在V22/2026-10-28T11-14-38-293Z，外部中断的另一次保留在V22/2026-10-28T10-41-08-494Z。新故事首次普通消息前的控制命令保存语义仍须在产品设计中明确，不能将handled当成保存回执。

## V28 文件确认

两个正常提交分别在message_end后约143/170ms从文件找到完整toolCallId结果，随后才通知chapter.committed；这不是fsync或掉电耐久证明。草稿经tool_execution_update到达真实网页，确认前DOM明确标为未提交，确认后显示第1章已提交；截图已单独查看。

只读反例中，Pi内存仍有1条提交而文件字节未变。桥接两秒内未确认文件条目，发送PERSISTENCE_NOT_CONFIRMED并终止自有Pi，未发送任何假成功通知；恢复只读属性后显式重开，磁盘提交数仍为0。两秒是探针超时值，正式产品须按条目大小与运行环境确定。证据：`D:\开源\test\pi-Story\p0\runs\V28\2026-10-28T11-26-07-529Z\result.json`。

## 后果

RPC get_entries 在 V24 已验证可携带 details、自定义条目与游标，但它是内存视图。章节提交必须以文件中的完整工具结果确认，不能将工具结束或 settled 当作保存回执。适配层还须沿用 V07 的单写者约束；此桥接是探针，不代表正式鉴权、锁恢复或完整产品界面已完成。
