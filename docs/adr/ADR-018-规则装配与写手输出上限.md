# ADR-018 规则装配与写手输出上限

日期：2026-10-29；2026-10-30结束开发并冻结。下方保留历次候选与结果，不把开发自评当成正式人工判定。

四角色规则以本包rules/<name>/SKILL.md保存，含name/description头信息。writer、review-matrix、state-projection由core经RuleSource装配；showrunner由before_agent_start加入固定系统提示。不依赖Pi按需Skill加载，不向角色提供读写工具。

沿用v3已验证的当前章停点、前文权威、视角/知识边界、原句证据、不把计划当事实、逐项保留不确定性的规则句，并改为当前core输入输出合同。没有取用未固定的inkos材料，未引入新的外部代码或许可来源。

规则示例用core实际parseWriter/Patches/ReviewOutput/DeltaProposal校验；主笔示例用Pi实际注册的参数schema校验。这只证明合同格式，不证明真实角色质量。规则长度与SHA-256在测量清单记录。

初始四角色maxTokens为8192。首次真实开发冒烟20261029T093029Z-6cf7ea0-smoke中，写手首稿正常结束（输出3130 Token）；编辑4次都在8192处截断，text为空，仅有思考内容。原始请求确认low与JSON模式均已正确下发。主笔开始整章重试后终止本次已确认失败的运行，保留中断记录，不将其作成功闭环。

编辑第1轮只调整输出上限8192→32768，仍为Flash/low，规则文本不变；32768低于固定模型上限384000。写手、记录员、核验员暂维持8192。模板回归先失败后通过；真实复测尚待完成。此参数调整保守计入编辑最多3轮的额度。写手最终上限待完整开发轮的输出/截断分布确定。

单次编辑诊断已用32768上限完成：17805输出Token（17658思考），JSON通过ReviewOutput校验。完整冒烟中编辑也已正常结束，暂保留该上限。

记录员第1轮：开发冒烟暴露遗漏via、rel键错误保留char:前缀、about误用裸人物键，且只修了反馈的第一个同类错误。仅补充标识符合同与事实→认知引用示例，要求按反馈检查同类所有行。新示例经生产validateDelta验证；改成裸人物键时实测拒绝。保持模型、low与8192不变。写手/主笔0轮，编辑1轮，记录员1轮；未读取验收部分。

记录员第2轮：20261029T100313Z-5afabd1-smoke中真实局部补丁及编辑复查完成，记录员两次均在8192 Token截断、text为空，未进入JSON合同判断。保持第1轮文本，单独上调记录员maxTokens至32768。写手/主笔0轮，编辑1轮，记录员2轮；真实复测待完成，不据截断推断引用合同好坏。

主笔第1轮：OPEN开发8条全部最终开书，但T01为27/32（84.375%），5次失败含3次长大纲JSON多余结尾大括号、1次无效圣经键、1次读取不存在章。只补充单根JSON对象与长大纲闭合边界，不自动修剪模型参数，也不同时调整键或读取规则。固定普通接口维持原样；Pi的constrainedSampling是可选功能，而DeepSeek官方strict工具协议需要Beta地址及不同schema限制（https://api-docs.deepseek.com/guides/tool_calls/），本轮不切换协议。主笔1轮、编辑1轮、记录员2轮、写手0轮。

主笔第2轮：第1轮复测T01=24/30=80%，T05=7/8，1946为首个请求连接中断。离线逐片拼接原始HTTP SSE后独立JSON.parse，原始参数同样以多余结尾括号结束，确认不是Pi拼接生成。第2轮仅针对大纲参数复杂度：明示narration字段清单，purpose/turn各用一个短句，保留完整台账/圣经要求，示例改为两章以展示重复对象和最终闭合。其他角色、模型、low与上限不变。主笔2轮、编辑1轮、记录员2轮、写手0轮。

主笔第3轮：CHAP中的919由英文原始请求生成了中文台账/大纲/brief，带动中文正文，并出现翻译或规范化作者引文的拒绝。只强化原始作者语言优先于界面/回执语言、生成规划保持正文语种、引用逐字保留Unicode标点。此后不再自动改主笔规则。写手第1轮为输出容量校准：919第2章实测stopReason=length、8192输出Token，按P2-O1上调至32768；不同时改写手文本。主笔3轮、写手1轮、编辑1轮、记录员2轮。

写手第2轮：第1轮容量配置在919完整3章上无截断，均为英文且在目标±30%内。针对原469的持续超长，发现规则一处仍引用旧target_words，而实际共享输入是targetWords。只统一字段名并明确“本章正文预算，不是最低长度或Token上限”、私下安排篇幅并收紧多余描写；不修改计数器、目标值或阈值。主笔3轮、写手2轮、编辑1轮、记录员2轮。

记录员第3轮（最后一轮）：DS09首轮6章仅3章最终通过，K02首次1/6、最终3/6。实际提议反复令expire.validUntil等于本章，或把place作为holder宾语；现有规则未明确这些事实操作合同。仅补事实提议的日期区间、谓词主宾类型与可选字段省略方式，给出“第2章离手物品：旧holder终点1，新增location”的完整示例。未改变core或提高重试次数。示例缺失回归先失败；补充后生产validateDelta通过，并明确拒绝本章终点和holder:place两种原反例，4项规则合同测试及项目check通过。模型、low、32768和其他角色规则不变。主笔3轮、写手2轮、编辑1轮、记录员3轮；接续DS09开发复测，不读取acceptance，不再自动增加记录员轮数。

编辑第2轮：DS10首次18变体全部跑完，24处注入均命中，但6处局部可修的插入句/死亡陈述被标structural，跳过了本可执行的局部修订（开发自评）。仅补scope：按最小忠实修复判定，远距离多处编辑、blocking或时间线类别不自动等于structural；整章原有叙述视角/时态改变、事件因果重构才需要结构性修订。没有改severity/objective准则、模型或容量。保留原失败、对照章额外观察和未知解释；接续同一DS10开发18变体。主笔3轮、写手2轮、编辑2轮、记录员3轮。

编辑第3轮（最后一轮）：第2轮24处注入scope全部匹配，严重度加范围20/24（开发自评）；额外观察仍将完整性截止条件强化成不得临时交接、把人物提问当成物品转移事实，以及把元叙述风格当客观错误。仅补objective证据成立条件：完整原句及来源、陈述主体、条件和时点、参与者全称/附加集合；不凭隐含前提断言矛盾，也不虚构未发生事件替真实矛盾开脱。不改scope/severity准则、模型、low或容量。主笔3轮、写手2轮、编辑3轮、记录员3轮；再跑同一DS10开发18变体后冻结，不自行增加额度，不读取验收内容调参。
