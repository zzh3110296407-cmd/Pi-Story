# ADR-021 作者控制与连续写作接线

日期：2026-11-01。状态：已实施（27 S2–S8），开发验证中；正式V4验收及作者终端检查待完成。

## 问题

P2能在一次工具调用中提交一章，但缺少作者控制命令、无人值守续写和运行中插话接线。作者控制、领域正史与Pi会话各有权威来源，不能让主笔写控制字段，也不能用适配层副本代替core折叠结果。

## 决定

`/intent`、`/focus`、`/ledger`走实际作者命令入口，调用core.authorControl后写入story.control；`/goal`、`/budget`调用authorGoal写入完整story.goal快照。故事提示之前拒绝命令，无参数打开预填编辑框，取消不写入；编辑框返回后重读当前分支。控制通知用story.notice，通知文本不成为作者原话或权威状态。台账set后的权威是作者命令条目，旧引文不再作为当前指令。

在before_agent_start边界从当前分支生成静态story_rules及author_intent/current_focus/story_progress动态段。同一代理运行中的工具回合不重复经过该边界，因此五个命令都发送story.notice；目标与预算通知携带已落盘的最新数值，按Pi原生steer队列投递，避免主笔继续沿用旧目标。通知不启动模型请求、不成为作者原话，core仍按权威状态执行闸门。新增ask_author通过实际UI/RPC对话框接收答案，答案写为作者消息；作者不在场或未答时暂停。update_bible/patch_outline仍交core校验，只能补充以后生效的设定和未写大纲，必须说明理由。工具公开的人物value直接复用core卡片schema，避免发布比实际领域契约更宽的字段。

自动继续使用Pi的agent_before_settle边界，追加自定义继续消息并返回continue:true，不伪造作者输入。是否继续取当前目标、正史章数、问题等待、预算/提供方错误及core失败计数；达到目标、关闭目标、同章连续两次失败、问作者、取消或错误时停止并写story.stop。目标与连续失败的写作入口拒绝仍由core负责，适配层不另设章数或失败计数。

写作工具运行时，真实input的steer增加会话插话序号；followUp不增加。宏开始捕获序号，core提交前复核；立即插话使旧尝试不提交，followUp保留本章。控制层变更由现有依据版本复核拦截跨越变更的旧结果，不更改core领域规则。

主笔与内部角色共享同一个BudgetGuard。主笔在before_provider_request按输入估算及输出上限预留，不足则ctx.abort，未知用量保留；已知主笔用量只在原生消息真正保存后确认，不能按值去重。预算完整快照即时生效。内部角色重试见ADR-022，每次实际尝试均占调用限额。

作者已认可最小BudgetCallRecord类型调整及临时压缩兼容层。固定Pi的摘要请求绕过主笔挂点，扩展只在压缩期间用公开provider接口逐次预留、结算并恢复原注册，保留Pi摘要与重试行为；具体边界和删除条件见[临时压缩兼容说明](../p3/compaction-compatibility.md)。只读上游不修改。跨进程中断恢复仍留给P4。

## 验证与限制

开发测试已覆盖五个命令、编辑期间状态更新、11个工具、三章自动续写、目标关闭、未答问题、连续失败、steer/followUp、主笔/压缩预算及I4/I7/I8/I9守约。实际SDK与模拟HTTP整书归档可重算H12/C04/C02/H09/C05。core预算契约调整后的P1全部11套件通过；正式门槛仍以产品V4上的27/29套件及J3为准。

P3实际费用账独立记录，12USD停止、15USD总上限，每本书2USD。测试数据冻结不替代产品V4冻结，开发不能读取新验收内容。长书写手输入增长按P3-O3记录，受控工作集仍保留既有C01豁免；临时压缩适配、未知用量预留和P4恢复缺口均须在验收报告披露。
