# ADR-019 P2测量、费用与人工判定

日期：2026-10-29；2026-10-30完成开发及测量工具并冻结。下方按时间保留实施记录，早期“真实请求0”“待交接”“未冻结”仅指当时。

## 运行边界

每次Pi运行有独立PI_CODING_AGENT_DIR、会话与书稿目录，位于P2 exec工作区。只加载本扩展、关闭其他扩展/Skill/模板/上下文文件；主笔与内部角色共用同一个固定Pi ModelRuntime。运行驱动只在E12/E13派发真实请求；开发只读取dev，acceptance仅冻结后的E13脚本读取。

## 全部调用计量

SDK主笔与内部角色都走runtime.streamSimple，确保Pi转换reasoning=low；测量驱动也覆盖API专用stream入口。限制Flash/low并关闭提供方自动重试。faux测试确认5次主笔/角色混合请求只记5次，不仅记录内部用量。主动结束后准备但未派发的请求记已知零费用并保留实际终止状态。产品侧P3的before_provider_request预算挂点尚未实现。

调用前向request-reservations.jsonl写持久化预留；完成后向usage-ledger.jsonl写一行，包含同一个requestId、套件/运行/角色/模型、用量和已知费用。最终行缺失或无用量时仍按预留计入。累计20美元停止，最大可能单次费用与累计额不得超过25美元，另有每次运行上限。金额按快照价格USD/百万Token计算，不写成供应商账单。

只保存onPayload处理后的请求体、HTTP响应体和Pi归一化回复；不记录请求URL、请求/响应头、认证选项或环境变量值。HTTP响应clone在归档前等待读完。原始记录保存失败时停止后续派发；费用完成行失败时保留已写入的预留，不把异常当成功或免费。

真实复测暴露clone.text()在断流时丢弃已收字节。现改为读取副本流，保留部分体与complete标记，独立保存provider_response后再等待HTTP归档；失败仍停止派发。测量可在工作目录创建STOP文件或接收SIGINT/SIGTERM后调用SDK abort，再走归档finally。原失败运行只保留当时实际证据，不追补虚构的响应。

直调角色不处在SDK主回合内，单独SDK abort不足以停止它。本地真实SDK+faux复现停止后直调仍返回ok=true。驱动现在拥有每案例AbortController，cancel同时取消SDK与该控制器，角色直调CommandContext使用同一signal，由core继续传给ModelPort并在完成边界复查取消。回归改用驱动cancel后返回TRANSPORT_FAILURE且没有追加调用；不改产品的P3插话接线。

已保存部分体的自然网络断流与写盘失败分开：断流保留原提供方error、未知预留和HTTP完整性标记，允许后续明确的作者回合；写盘/记账失败及HTTP 4xx/5xx继续停止派发。CHAP按19的固定“Write the next chapter.”回合继续直到目标或12回合，不因单个transport回复提前结束；不自动重试提供方请求。开发可用--case选固定子例修复后补测，验收拒绝此参数。聚合拒绝重复runId/套件重复次序，并显式报告执行是否完整，比例达标不能代替章节目标完成。

## 领域路径

记录员直调与标准宏共用generateStateDelta（格式修复加一次领域反馈），之后宏仍通过原提交闸门。编辑直调共用generateReview/generatePatch/checkDraft等领域函数。直调测量不把构造章节伪装成已审稿的产品提交。

## 人工判定与重新评分

原始产物与人工判定分开。执行会话不创建或修改judgments，缺失时指标标为待判定。AI预判不能自动当作作者认可；接受的判定必须保留作者核对依据、原AI判与改判。

判定文件是judgments/下JSON：schema为story/p2-judgments@1，scores数组每行包含metric、component、sampleId、runId、pass布尔值、status（ai_preliminary或author_approved）；认可文件另含approval.evidence（作者确认依据），并可附原AI判断、原始证据定位、改判与分层信息。重复样本拒绝。precision/recall类的component分别为precision、recall，其余为value。读取时只计author_approved；文件及认可由测试集会话/作者维护。

与20 §5的交接方式：上述scores行同时保留itemId、preJudge、authorVerdict、final、note、judgedBy与日期，itemId对应sampleId，final对应当前component的pass；preJudge与作者改判不得覆盖。规范化字段用于程序计算，原判字段用于核对，二者放在同一份JSON中；approval.evidence链接实际作者认可依据。执行会话不生成这些人工判定文件。

观察指标也复用此格式：P2-O6的component为fixed或introduced，sampleId为`<caseId>:<复查reviewId>:<原/新观察ID>`，pass表示作者确认该问题实际被修好/实际新引入。每次修订的两组都要明确给出；某组为零时，用末段none、pass=false及note说明“已核对，无此类问题”，不可用缺失组冒充零。两组齐备后actualNet为确认修好数减确认新引入数；仅有一组或AI预判仍待定。P2-O7的component为relevant，每个实际装配条目一行，sampleId包含case/章/角色/条目ID，pass表示相关；报告样本n、比例及Wilson区间。只计同一运行且author_approved的记录，不用模型自判替代人工。

run-suite.mjs --rescore <运行目录>只读raw及judgments，核对所有引用的压缩原始文件摘要，重算数值并与metrics.json结构比较。--write用于作者补判后的显式更新，不改raw。--aggregate合并同一冻结代码的两个验收重复：程序指标报告各重复的样本加权值、两次算术平均与合并n/区间；人工指标按合并样本计算。最低样本量不足不通过。

P2-UNIT/GUARD/FOLD/REG通过同一入口运行；跳过、todo或失败不算通过。P2-REG子记录放P2目录且不写judgments，不覆盖P1报告。P2源码脚本已加入项目类型检查。

归档提交只允许增加runs记录。验收清单同时记录冻结源码提交repositoryCommit与当时HEAD（evidenceHead），每次运行前验证排除runs后的整个源码树与冻结提交一致并且没有未提交源码修改。不用分支或重置工作区来维持证据。

观察统计按实际宏/直调开始、结束边界分配请求，首次宏包含开书，最后宏之后的请求单列overhead；同时报告逻辑请求和实际HTTP尝试，不把取消前准备的零派发请求当成付费调用。金额从原始归一化用量或对应预留重建，与费用账保持同一规则。风险仅计实际提交，未确认比例限定事实/认知/关系新增或upsert，转述和伏笔生命周期另列。局部修订输出程序代理净效果，真实净效果及相关条目精确率保留待人工，不把模型自判当人工结论。后续运行raw配置项保存规则长度、估算Token及摘要，支持离线复算观察值。

收尾入口：`P2-RESCORE --freeze <提交> --runs <运行目录...>`核对同一冻结提交的8个真实验收运行及5个确定性套件，保存只读比较结果；缺失重复、重复目录、源码不一致均拒绝。`P2-Z --freeze <提交>`扫描仓库与整个P2工作区（含gzip解压内容），保存费用快照；不读取.env，仅记录其路径，非已知合成环境文件使扫描不通过。候选密钥仅记录类别、行号与摘要，绝不输出原值。上游公开单词Bearer样例只有整文件等于固定Pi基线才能排除，合成dataset-guard负例只排除固定值与固定目录。两项收尾均无模型请求，结果支持同一--rescore离线重算。确定性套件同样支持--freeze，记录冻结提交及证据HEAD。

全范围预扫描另识别19个依赖公开候选：SDK文档/类型中的认证示例、AWS文档示例ID、ssh2编码器标记和公开TLS测试私钥。不是按node_modules整体忽略。public-secret-fixtures.json记录固定Pi锁文件提交、3个包的版本/registry URL/SHA-512完整性、16份文件的原归档成员名/整文件SHA-256及候选摘要。生成时从E0离线npm缓存取包，先与固定提交锁文件的integrity核对，再经tar标准输出逐字节核对安装文件；未下载或升级依赖。扫描只在包路径、整文件摘要、候选摘要全部匹配时排除。修改公开文件再插入新密钥的回归仍检出且不再享受该文件排除。原始20候选失败结果保留；扫描器自身的公开示例字串改用通用单词规则，仍必须有整份Pi原文基线证明。

`--all-real`另外从费用预留的运行ID全集定位原始归档，重新计算H12/H09/C02/C04/C05并按全部调用合并，不将开发失败或诊断请求排除以取得通过。未归档的付费运行会直接拒绝汇总。将内部预留数与已保存role_call/CallRecord对照：缺失观察仍进入H12/C04分母，缺失输入观察使相应零次指标保持未知。独立编辑诊断没有产品CallRecord，开发强停也可能造成记录缺口；这些在全部真实调用汇总中如实失败/未知，不能由后续成功验收抹掉。正式两次质量指标仍按原--aggregate规则独立计算，历史门槛另列。
