# ADR-008 结构化输出

日期：2026-10-28。依据：V19的分组结果、原始响应与失败分析。

在thinking low条件下，强制工具选择和严格工具选择各30次均收到API400，错误为Thinking mode does not support this tool_choice。固定目录声明支持严格工具，并不保证与强制选择、思考档位的组合可用；不反复重跑相同不兼容组合。

| 组别 | 首轮可解析 | 首轮符合schema | 一次修复后 |
|---|---:|---:|---:|
| JSON，maxTokens2048，3章各10次 | 26/30 | 19/30 | 25/30 |
| JSON，maxTokens8192，3章各10次 | 29/30 | 23/30 | 30/30 |

原组有输出触顶、额外根type字段和缺object。先用一个length失败与一个非length失败做仅提高上限的对照，实际HTTP payload除max_tokens外deepEqual；两次均成功。这不是非length失败归因于上限的普遍证明。随后新JSON组保持原提示、schema和low档位，仅提高输出上限；7个失败各做一次附真实validator错误路径的修复，7次均成功。程序没有删除额外字段或补写object。

决定：采用JSON模式、8192上限、最多一次带具体错误反馈的格式修复，预算同时预留原调用与修复。首轮与修复后分别报告。后续core仍要校验业务引用、状态迁移与正文证据；这里仅证明当前样本上的格式与句号范围可用。

提议使用12接口中的confirmed/uncertain、uncertainReason和整数sentences，不把状态层provisional直接混入。当前是仅新fact upsert的明确子集：12通用多操作提议中object可选，但本子集要求完整新事实，最终Fact按09需要object。其余事件数组在此探针中固定为空，不能把结果外推为完整状态投影质量。

早期58次先导使用了另一份简化字段，已单列并安全停止，58请求、58响应、58账行，无在途遗失。连同原90次、原11次修复、2次对照、新30次及7次修复，V19共198次尝试全部保留并计预算。API400未返回用量，费用按保守预留计，不是供应方账单。
