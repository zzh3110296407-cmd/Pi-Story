# ADR-002 持久化与单写者

日期：2026-10-28。依据：V03、V07、V08、V09；文件确认适配由 V28 补充。

V07只读反例证明事件、settled和get_entries内存均不能证明已保存。决定以会话文件中的完整toolCallId对应结果为确认条件；确认前只显示提交中，失败时结束自有进程，重新打开后从文件重建。不得将内存覆盖层当成第二份权威。

Pi没有原生阻止两个进程写同一故事。使用适配层单写者锁；探针以wx独占创建，在第二个打开操作spawn之前拒绝。

20次强杀均在tool_end后而实际写入前，未发现半章，但不能证明写入过程中的崩溃或掉电耐久。正式承诺在P4继续以故障证据界定。残缺行在加载时被忽略，继续追加后原无效行仍在文件中，父子关系未出现悬空。

V08能识别有调用无结果并补中断记录，重开后可继续。V09单条details在100KiB、1MiB、5MiB、20MiB下均成功；20MiB的耗时与内存上升明显。v1.0约十章可保留整章提交结果，不能把20MiB已测值称为大小上限。
