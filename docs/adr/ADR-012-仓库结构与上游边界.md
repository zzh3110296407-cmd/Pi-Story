# ADR-012 仓库结构与上游边界

日期：2026-10-28。状态：采用。

## 背景与决定

P0沿用了Pi仓库并追加探针提交，而非新建仅消费打包Pi的独立仓库。保留分叉能继续利用已验证的固定源码、历史与检查；本项目选择通过目录边界控制改动范围。

根 `packages/` 固定于 `b06c1f2cf1dea6af8748ddeee18c23587d2cb7c6`，作为只读上游。正式代码在顶层 `story/`，独立管理npm清单；`core`、`pi-story`、`runner`、`evals` 位于 `story/packages/*`，本机Node服务 `bridge` 和浏览器端 `web` 分别位于 `story/apps/*`。六个单元各自拥有包清单，按阶段创建；当前只建立项目检查入口。

`bridge` 与 `web` 分包，使Pi和Node服务依赖归属桥接端，浏览器只通过HTTP/WebSocket接口通信，不引用后端包。`runner` 与 `evals` 分包，使成书、L0循环和B0/B1/B2基线生成独立于ConStory评测、人工评分、报告与Python评分器调用；依赖方向为 `evals` 调用 `runner`，产品代码不引用评测代码。具体职责映射见 [story目录说明](../../story/README.md)。

依赖约束沿用00 §13.2和10 V5：只有 `pi-story`、`bridge`、`runner` 可以引用Pi；`core` 保持纯TypeScript，不引用Pi、`pi-story` 或 `bridge`；`web` 不引用任何后端包，产品代码不引用测试与评测代码。后续建立各业务包时，以独立依赖清单和依赖/import检查落实这些约束；根Pi工作区继续服务上游代码。

`p0/` 和 `docs/p0/` 保留为验证材料，原始证据与历史路径不批量重写。当前工作仓库是 `D:\AI\Story Dome\Story\pi-Story`，旧同名副本不作为后续开发位置。

## 规则与检查

AGENTS.md开头定义本项目的目录、检查、测试产物与Git规则。原Pi文本保留供上游维护参考；它的提交格式、发布和贡献流程不套用于故事项目。当前用户授权和执行方案决定是否提交，不从上游条款额外推导审批要求。

`story/scripts/check-upstream.mjs` 用真实Git分别对比HEAD、暂存区、工作区与完整基线，并检查未忽略的新文件。根 `npm run check:upstream` 和 `npm --prefix story run check` 均可直接执行；根 `npm run check` 先检查边界，再执行原有全部检查。

基线缺失或Git失败时检查失败，不自动下载或更换基线。CI的build-check-test作业设置fetch-depth为0，保证固定提交可见。没有增加发布或远程权限操作。

## 后果

上游一致性针对Git源树；被忽略的依赖、构建和模型数据不视为源码修改，仍必须放到D盘测试根。升级Pi需要作者明确授权并同时审阅基线、构建数据及兼容性，不以直接改 `packages/` 实现故事功能。

后续阶段按上述目录映射实施；本次不迁移P0探针为生产代码，不改变既有设计中的领域合同。结构选择替代了独立仓库布局，其余阶段的功能范围不变。
